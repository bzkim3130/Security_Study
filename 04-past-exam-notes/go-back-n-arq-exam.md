# 기출노트: Go-Back-N ARQ

## 한줄 요약
> Go-Back-N은 오류 발생 시 그 이후 전체를 재전송하고, Selective Repeat은 오류난 것만 재전송한다 — 윈도우 내 순차성 요구 여부가 핵심 차이다.

## 1. Go-Back-N ARQ 개념

- 슬라이딩 윈도우(Sliding Window) 기반 프로토콜
- 송신측이 윈도우 크기만큼 연속으로 패킷을 먼저 보냄
- 수신측은 **순서대로 온 것만** ACK, 순서 어긋나면 NAK(또는 무시) → 그 지점부터 **전부 재전송**

## 2. 문제 풀이 예시 (문항: (가)=?, (나)=?)

**정답**: ③ (가)=P2, (나)=P3

**풀이 흐름**
```
송신: P1 → P2 → P3 → P4 → ...
                  │
             (P2에서 오류/손실 발생)
                  ▼
수신측: P1은 정상 수신(ACK1)
        P2 손실 → 이후 P3, P4가 도착해도 순서가 안 맞아 버려짐(폐기)
        수신측은 계속 ACK1(마지막으로 순서 맞은 것)만 반복 전송
                  │
                  ▼
송신측: 타임아웃 또는 중복ACK 감지
        → P2부터 그 이후 전부(P2, P3, P4...) 재전송 (Go-Back-N)
```
- (가) = 처음 손실된 패킷 **P2**
- (나) = 재전송이 시작되는 지점(P2부터 다시) 이후 이어지는 **P3**

## 3. Go-Back-N vs Selective Repeat

| 구분 | Go-Back-N | Selective Repeat |
|---|---|---|
| 재전송 범위 | 오류 발생 지점부터 **전체** 재전송 | **오류난 패킷만** 개별 재전송 |
| 수신측 버퍼 | 순서 어긋난 패킷은 버림(폐기) | 순서 어긋나도 **버퍼링**해서 나중에 정렬 |
| 구현 복잡도 | 단순 | 복잡(개별 ACK/NAK, 버퍼 관리 필요) |
| 효율성 | 오류 많으면 비효율적(불필요한 재전송 많음) | 효율적(필요한 것만 재전송) |

## 4. Stop-and-Wait와의 비교

- **Stop-and-Wait**: 한 번에 패킷 1개만 보내고 ACK 기다림(윈도우크기=1) → Go-Back-N/Selective Repeat은 여러 개를 한번에 보내는 슬라이딩 윈도우 방식이라 효율적

## 암기 팁
- **"Go-Back-N = 다시 처음부터(N개 통째로)"**, **"Selective Repeat = 콕 집어서 그것만"**
- **수신측 동작 차이**: "Go-Back-N은 순서 어긋나면 버림, SR은 일단 챙겨둠(버퍼링)"

## 헷갈리는 포인트
- Go-Back-N은 수신측이 순서 어긋난 패킷을 **폐기**하지만, Selective Repeat은 **버퍼에 저장**해뒀다가 나중에 순서를 맞춤 — 이 버퍼링 여부가 핵심 차이
- ACK/NAK 방식이 프로토콜마다 세부 구현이 다를 수 있음(누적ACK 방식 등) — 문제에서 주어진 조건을 우선 따를 것
