# 기출/오답노트 - 네트워크보안

## 문제 1: 서브넷마스크 구하기 (192.168.1.0, 8개 서브넷 / 30 호스트)

**조건**: Class C(192.168.1.0), 8개 서브넷, 서브넷당 30개 호스트 필요

**풀이**
1. 8개 서브넷 필요 → 2ⁿ ≥ 8 → n=3 (서브넷 비트 3개 빌림)
2. 30개 호스트 필요 → 2ʰ-2 ≥ 30 → h=5 (호스트 비트 5개 필요, 2⁵-2=30)
3. 3(서브넷)+5(호스트)=8비트 → 마지막 옥텟 정확히 소진
4. 서브넷마스크 = 255.255.255.**224** (/27)

**검증**: /27 → 호스트비트 5개 → 2⁵-2=30 ✅, 서브넷 8개(2³) ✅

## 문제 2: 서브넷마스크 구하기 (203.230.15.0, 30개 서브넷 / 5 호스트)

**조건**: Class C(203.230.15.0), 30개 서브넷, 서브넷당 5개 호스트 필요

**풀이**
1. 30개 서브넷 필요 → 2ⁿ ≥ 30 → n=5 (서브넷 비트 5개)
2. 5개 호스트 필요 → 2ʰ-2 ≥ 5 → h=3 (호스트 비트 3개, 2³-2=6≥5)
3. 5(서브넷)+3(호스트)=8비트
4. 서브넷마스크 = 255.255.255.**248** (/29)

**검증**: /29 → 호스트비트 3개 → 2³-2=6 (5 이상 충족) ✅, 서브넷 32개(2⁵, 30 이상 충족) ✅

## 두 문제 비교

| 구분 | 문제1 (192.168.1.0) | 문제2 (203.230.15.0) |
|---|---|---|
| 요구 서브넷 수 | 8개 | 30개 |
| 요구 호스트 수 | 30개 | 5개 |
| 먼저 고정되는 쪽 | 호스트 비트(30=2⁵-2, 딱 맞음) | 서브넷 비트(30→2⁵=32, 딱 맞음) |
| 서브넷마스크 | 255.255.255.224 (/27) | 255.255.255.248 (/29) |

## 풀이 전략 요약

**어느 조건이 "먼저 고정"되는지 확인**: 주어진 숫자가 2ⁿ 또는 2ⁿ-2 패턴에 딱 맞아떨어지는 쪽을 먼저 계산 → 반대쪽은 8비트에서 빼서 자동 결정

```
서브넷 비트 + 호스트 비트 = 8 (Class C 마지막 옥텟 기준)
```

## 오답 이유 / 헷갈린 포인트
- 호스트 수 계산 시 -2(네트워크주소, 브로드캐스트주소 제외)를 빼먹기 쉬움
- 어느 조건부터 계산해야 할지 헷갈릴 때는 "2의 거듭제곱에 정확히 맞아떨어지는 숫자"부터 처리

## 문제 3: CIDR /22 서브네팅 (200.107.16.17/22)

**조건**: 200.107.16.17/22에서 옳지 않은 것 고르기 (보기: 주소개수/네트워크주소/브로드캐스트주소/CIDR지원여부)

**풀이 (이진수 방식)**
```
세 번째 옥텟(16)을 이진수로: 00010000
/22 → 네트워크비트 22개 = 처음 두 옥텟(16)+세번째 옥텟에서 6비트
세 번째 옥텟 8비트 중: 앞 6비트=네트워크, 뒤 2비트=호스트

00010000
└──6비트──┘└2비트┘
 (고정)     (00~11 변화)

호스트비트 2개 → 00,01,10,11 → 세번째 옥텟 값: 16,17,18,19
```

- 총 주소개수: 2¹⁰(호스트비트 10개: 세번째옥텟2개+네번째옥텟8개) = **1024개**
- 네트워크 주소: **200.107.16.0**
- 브로드캐스트 주소: **200.107.19.255** (❌ "200.107.18.255"로 나오면 오답)

**정답**: 브로드캐스트 주소를 200.107.18.255라고 한 보기가 틀림(정답은 19.255)

## 오답 이유 / 헷갈린 포인트
- 블록 크기(4)만 보고 마지막 값을 "시작+블록크기"로 착각(16+4=20이 아니라, 16~19 범위이므로 끝은 19)
- 이진수로 직접 풀면: 호스트비트가 00~11로 전부 변하는 지점까지가 브로드캐스트 주소

## 문제 4: IP 단편화 오프셋 계산

**조건**: Header Length=5, Total Length=1020바이트, Fragment Offset=340(8바이트단위), Identification=49153, MF=1

**풀이**
1. 데이터 payload = 1020−20(헤더) = 1000바이트
2. 실제 시작 바이트 = 340×8 = 2720, 끝 = 2720+1000−1 = 3719
3. 다음 조각 Offset값 = 3720÷8 = **465**

**정답**: 다음 조각의 Fragment Offset 필드값은 465

## 오답 이유 / 헷갈린 포인트
- Header Length(4바이트 단위)와 Fragment Offset(8바이트 단위)의 단위 차이를 혼동
- Identification은 조각마다 바뀌지 않고 원본 패킷 전체에서 동일하게 유지된다는 점을 놓치기 쉬움
- 재조립은 라우터가 아닌 목적지 호스트에서 수행
