# 디바이스 인증기술

## 한줄 요약
> 디바이스 인증은 "이 기기가 맞는지"만 확인하는 것이라 책임추적성(누가 썼는지)은 제공하지 못하며, 실제 장점은 보안성/상호연동성/경제성이다.

## 1. 핵심 기술 요소

| 기술 | 역할 |
|---|---|
| 802.1X | 포트 기반 접근제어 프레임워크 |
| EAP (Extensible Authentication Protocol) | 다양한 인증방식을 담는 틀 |
| TPM (Trusted Platform Module) | 기기 내 하드웨어 기반 신뢰 루트, 키 저장 |
| NAC (Network Access Control) | 네트워크 접속 전 기기 상태(백신, 패치 등) 검사 |
| MAC 필터링 | MAC 주소 기반 단순 접근제어(취약, 위조 쉬움) |
| PKI/X.509 인증서 | 기기별 인증서 발급으로 신원 증명 |

## 2. 디바이스 인증기술의 장점 (실제 기출 선택지 기준)

| 장점 | 이유 |
|---|---|
| 보안성 (O) | 비인가 기기의 네트워크 접근을 원천 차단 |
| 상호연동성 (O) | 802.1X/EAP 등 표준 기반이라 다양한 벤더 장비와 연동 가능 |
| 경제성 (O) | 중앙집중식 관리로 개별 통제 대비 운영비용 절감 |
| 책임추적성 (X) | 디바이스 인증은 "어떤 기기인지"만 확인 — "누가 그 기기를 썼는지"는 사용자 인증/로그의 역할 |

## 3. 왜 책임추적성은 아닌가

```
디바이스 인증 = "이 노트북이 등록된 노트북 맞다" (기기 신원 확인)
사용자 인증 = "이 사람이 김철수 맞다" (사용자 신원 확인)
로깅/감사 = "언제 누가 무엇을 했다" (행위 기록)

책임추적성(Accountability) = 사용자 인증 + 로깅의 역할
                            → 디바이스 인증만으론 "누가"를 특정 못함
```

## 암기 팁
- **"보상경 O, 책 X"** — 보안성/상호연동성/경제성은 O, 책임추적성은 X (실제 기출 선택지 기준 정리)
- **"기기는 알아도 사람은 모른다"** — 디바이스 인증의 근본적 한계
- 802.1X = "출입증 검사하는 문지기 시스템", EAP = "출입증 종류(지문/카드/비번 등)를 담는 봉투"

## 헷갈리는 포인트
- 디바이스 인증만으로 "누가 그 행동을 했는지"까지 보장한다고 착각하기 쉬움 — 책임추적성은 별도의 사용자 인증+로그 체계가 필요
- MAC 필터링은 디바이스 인증기술 중 가장 취약한 방식 (MAC 주소는 쉽게 위조 가능) — PKI/TPM 기반이 훨씬 안전

## 관련 기출/문제
- 디바이스 인증기술의 장점 중 아닌 것 찾기 (책임추적성이 함정)
- 802.1X, EAP, TPM, NAC 역할 구분
- 디바이스 인증 vs 사용자 인증 차이
