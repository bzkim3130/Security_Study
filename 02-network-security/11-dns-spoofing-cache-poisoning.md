# DNS 스푸핑 vs DNS 캐시 포이즈닝

## 한줄 요약
> DNS 스푸핑은 "위조 DNS 응답을 보내는 행위" 전체를 가리키는 큰 개념이고, 캐시 포이즈닝은 그 결과로 리졸버의 캐시 자체를 오염시켜 TTL 만료 전까지 다수 사용자에게 지속적 피해를 주는 특정 유형이다.

## 1. 개념 관계도

```
DNS 스푸핑 (큰 우산 개념)
   │
   └── DNS 캐시 포이즈닝 (스푸핑의 한 결과/하위유형)
         → 재귀 리졸버 캐시에 악성 레코드 주입
         → TTL 만료 전까지 그 리졸버를 쓰는 "모두"가 피해
```

## 2. 비교표

| 구분 | DNS 스푸핑 | DNS 캐시 포이즈닝 |
|---|---|---|
| 범위 | 위조 응답을 보내는 모든 행위(포괄) | 리졸버 캐시 오염(특정 결과) |
| 대상 | 특정 피해자 1명일 수도 | 그 리졸버를 쓰는 다수 사용자 전체 |
| 영향 범위 | 좁을 수 있음(로컬) | 넓음(캐시 만료 전까지 지속) |
| 지속성 | 공격 진행 중에만 | TTL 만료까지 지속됨(공격 끝나도 남음) |

## 3. 동작 흐름

```
[정상]
Client → Query → Recursive Resolver → Query → Authoritative Server
                                     ← 정상 응답 ←
Client ← 정상 응답 ←

[캐시 포이즈닝]
공격자가 Resolver의 Query ID/포트를 예측 or Race Condition으로
정상 응답보다 먼저 위조 응답을 Resolver에 주입
   → Resolver가 위조 레코드를 캐시에 저장(오염)
   → 이후 이 Resolver를 쓰는 모든 사용자가 악성 IP로 유도됨(TTL까지)
```

## 4. 대표 공격: Kaminsky Attack (2008)

- Query ID(16비트, 65536가지)를 짧은 시간 내 대량으로 위조 응답을 보내 예측·매칭시켜 캐시를 오염시키는 기법
- Birthday Attack 원리를 활용해 성공 확률을 높임

## 5. 방어 대책

- **DNSSEC**: 응답에 전자서명을 붙여 위변조 검증
- **Query ID 랜덤화**: 예측 어렵게
- **소스 포트 랜덤화**: 예측 범위 확대
- **TTL 최소화**: 오염되어도 피해 지속시간 단축

## 암기 팁
- **"스푸핑은 우산, 포이즈닝은 우산 아래 비 한 종류"**
- **"포이즈닝 = 여러 사람이 마시는 우물에 독 타기"** — 캐시를 쓰는 모두가 피해
- ARP 스푸핑과 DNS 스푸핑은 다른 계층: **ARP=2계층(로컬), DNS=응용계층(도메인 해석)**

## 헷갈리는 포인트
- 스푸핑은 "행위" 자체를 지칭, 포이즈닝은 "결과(캐시 오염 상태)"를 지칭 — 포함관계이지 대등한 별개 개념 아님
- 캐시 포이즈닝은 공격이 끝나도 **TTL이 만료될 때까지 피해가 지속**됨 (일회성 아님)
