# IP 단편화(Fragmentation) 오프셋 계산

## 한줄 요약
> Fragment Offset은 8바이트 단위로 표기되므로 실제 바이트 위치를 구하려면 ×8을 해야 하고, Identification 값은 모든 조각에서 동일하며 재조립은 라우터가 아닌 목적지 호스트에서 이루어진다.

## 1. 핵심 공식

```
실제 바이트 오프셋 = Fragment Offset 필드값 × 8
다음 조각의 Offset 필드값 = (이전 조각의 끝 바이트 위치) ÷ 8
```

## 2. 계산 예시

**조건**: Header Length=5(20바이트), Total Length=1020바이트, Fragment Offset=340(8바이트 단위), Identification=49153, MF=1

**풀이**
1. 데이터 payload = Total Length(1020) − Header(20) = **1000바이트**
2. 이 조각이 커버하는 실제 바이트 범위: 시작 = 340×8 = 2720, 끝 = 2720+1000−1 = **3719**
3. 다음 조각의 시작 바이트 = 3720
4. 다음 조각의 Offset 필드값 = 3720 ÷ 8 = **465**

```
[현재 조각]
Offset필드(340) × 8 = 실제시작(2720)
데이터길이 1000바이트 → 실제끝(3719)
      │
      ▼ (다음 조각 시작)
실제시작(3720) ÷ 8 = 다음 Offset필드값(465)
```

## 3. 단위 혼동 주의

| 필드 | 단위 |
|---|---|
| Header Length(IHL) | **4바이트** 단위 (예: 5 → 20바이트) |
| Fragment Offset | **8바이트** 단위 (예: 340 → 2720바이트) |

## 4. 관련 개념 정리

| 개념 | 내용 |
|---|---|
| Identification | 원본 패킷을 식별하는 값, **모든 조각(fragment)에서 동일하게 유지** |
| MF(More Fragments) | 1=아직 뒤에 조각이 더 있음, 0=이 조각이 마지막 |
| 재조립 위치 | **목적지 호스트**에서 수행(중간 라우터에서는 재조립 안 함) |

## 암기 팁
- **"Offset은 8바이트 단위, Header Length는 4바이트 단위"** — 숫자가 헷갈리면 이 규칙부터 떠올리기
- **"ID는 그대로, MF는 마지막만 0, 재조립은 목적지"** 세트로 암기
- 계산 순서: **"데이터길이 구하고 → 시작+끝 바이트 구하고 → ÷8로 다음 Offset값"**

## 헷갈리는 포인트
- Header Length(IHL)와 Fragment Offset의 **단위가 다름**(4바이트 vs 8바이트) — 이걸 헷갈려서 계산 오답
- Identification은 조각마다 바뀌는 게 아니라 **원본 패킷 전체에서 동일** — "각 조각마다 새로 부여된다"는 오답 함정
- 재조립은 **라우터가 아니라 목적지 호스트**에서 수행 — 라우터가 조립한다는 오답 함정

## 관련 기출/문제
- Fragment Offset 필드값으로 실제 바이트 위치 계산
- 다음 조각의 Offset 필드값 역산
- Identification/MF 필드 특성 문제
- 재조립 수행 위치(목적지 호스트)

## 💬 내 코멘트
- 데이터 payload +  Fragment Offset = 다음 조각 시작 바이트

- 데이터 payload = Total Length - Header Length (X4)
- Fragment Offset = (X8)
