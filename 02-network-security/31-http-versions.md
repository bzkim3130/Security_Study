# HTTP 버전별 비교 및 진화

## 한줄 요약
> HTTP는 0.9(단순)→1.0(캐시/헤더)→1.1(지속연결)→2(멀티플렉싱)→3(QUIC/UDP)로 진화하며, HOL Blocking이 HTTP/2에서 애플리케이션 레벨은 해결되지만 TCP 레벨에서 남아있던 것을 HTTP/3(QUIC/UDP)가 완전히 해결한다.

## 1. 버전별 비교표

| 버전 | 연결방식 | 핵심 기능 | 전송계층 |
|---|---|---|---|
| HTTP/0.9 | 요청마다 새 연결 | GET만 지원, 헤더 없음 | TCP |
| HTTP/1.0 | 요청마다 새 연결(기본) | 헤더, 상태코드, 캐시 개념 도입 | TCP |
| HTTP/1.1 | **지속연결(Persistent/Keep-Alive)** | 파이프라이닝(제한적), 호스트헤더 | TCP |
| HTTP/2 | 지속연결 + **멀티플렉싱** | 바이너리 프레이밍, 헤더압축(HPACK), 서버푸시 | TCP |
| HTTP/3 | **QUIC(UDP기반)** | 멀티플렉싱 유지, TCP의 HOL Blocking 완전 해결 | **UDP(QUIC)** |

## 2. 연결 방식 도식화

```
[HTTP/1.0] 요청마다 3-way handshake 새로 함 (느림)
Req1 → [연결→응답→연결종료] 
Req2 → [연결→응답→연결종료]

[HTTP/1.1] Keep-Alive로 연결 재사용, 근데 순차 처리(파이프라이닝은 제한적)
[연결 유지] Req1→Resp1 → Req2→Resp2 → Req3→Resp3  (한줄로 순서대로)

[HTTP/2] 멀티플렉싱 - 하나의 연결에서 여러 요청/응답 동시 처리
[연결 유지] Req1,Req2,Req3 동시 전송 → Resp1,Resp2,Resp3 뒤섞여 도착 가능

[HTTP/3] QUIC(UDP) - 스트림별로 완전히 독립적, 패킷손실도 스트림별로만 영향
[UDP 기반 QUIC] 스트림1 손실 → 스트림2,3엔 전혀 영향 없음
```

## 3. HOL(Head-of-Line) Blocking 해결 단계

| 단계 | 상태 |
|---|---|
| HTTP/1.1 | HOL Blocking 발생(요청이 순서대로 밀림) |
| HTTP/2 | **애플리케이션 레벨**은 해결(멀티플렉싱), 하지만 **TCP 레벨**에서 패킷 손실 시 전체 스트림이 지연되는 문제는 여전히 존재 |
| HTTP/3 | QUIC(UDP기반)이 **TCP 레벨 HOL Blocking까지 완전 해결** — 스트림 간 독립적 처리 |

## 4. 핵심 개념 용어

- **Keep-Alive(지속연결)**: 하나의 TCP 연결을 여러 요청에 재사용(HTTP/1.1부터)
- **멀티플렉싱(Multiplexing)**: 하나의 연결에서 여러 요청/응답을 동시에 주고받음(HTTP/2부터)
- **HPACK/QPACK**: 헤더 압축 기법(HTTP/2=HPACK, HTTP/3=QPACK)
- **서버 푸시(Server Push)**: 클라이언트 요청 전에 서버가 미리 리소스를 보내주는 기능(HTTP/2)
- **QUIC**: UDP 기반의 새로운 전송 프로토콜, HTTP/3의 기반

## 암기 팁
- **"공백연다삼"**: 공식(0.9)-백지(1.0,헤더없다시피)-연결(1.1,Keep-Alive)-다중(2,멀티플렉싱)-삼(3,QUIC) — 버전별 핵심 키워드로 암기
- **Keep-Alive(1.1) vs 멀티플렉싱(2) 구분**: "1.1은 순서대로 한줄, 2.0은 동시에 여러줄"
- **"HOL Blocking, 2에서 반만 해결, 3에서 완전 해결"** — 애플리케이션 레벨 vs TCP 레벨

## 헷갈리는 포인트
- HTTP/2가 멀티플렉싱을 도입했다고 해서 **HOL Blocking이 완전히 사라진 건 아님** — TCP 자체의 순서보장 특성 때문에 패킷 손실 시 여전히 지연 발생(TCP 레벨 HOL Blocking)
- HTTP/1.1의 "파이프라이닝"과 HTTP/2의 "멀티플렉싱"을 혼동하기 쉬움 — 파이프라이닝은 요청은 연달아 보내지만 **응답은 순서대로**(제한적), 멀티플렉싱은 응답이 **뒤섞여도** 무방
- HTTP/3는 TCP가 아니라 **UDP 기반(QUIC)** — "HTTP는 항상 TCP 위에서 동작한다"는 통념이 깨지는 지점

## 관련 기출/문제
- 버전별 연결방식/핵심기능 매칭
- HOL Blocking이 해결되는 단계(애플리케이션 vs TCP 레벨)
- HTTP/3가 UDP(QUIC) 기반이라는 점
- Keep-Alive vs 멀티플렉싱 차이
