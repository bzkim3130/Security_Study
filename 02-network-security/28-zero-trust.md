# 제로 트러스트(Zero Trust) 핵심 구성요소

## 한줄 요약
> "절대 신뢰하지 말고 항상 검증하라(Never Trust, Always Verify)"는 원칙 아래, NIST SP 800-207의 PE(정책엔진, 판단)-PA(정책관리자, 관리)-PEP(정책시행지점, 집행) 3요소가 매 접근요청마다 동작한다.

## 1. 전통적 경계보안 vs 제로 트러스트

| 구분 | 전통적 경계보안(Perimeter) | 제로 트러스트 |
|---|---|---|
| 신뢰 기준 | 내부망=신뢰, 외부=불신 | **위치 무관**, 모든 접근을 매번 검증 |
| 접근제어 | 한번 내부 진입하면 광범위 접근 허용 | **최소권한** + 세션마다 재검증 |
| 경계 개념 | 방화벽 등 경계선 중심 | 리소스 단위(마이크로 세그먼트) 중심 |

## 2. NIST SP 800-207 핵심 3요소

| 구성요소 | 역할 |
|---|---|
| PE (Policy Engine, 정책엔진) | 접근 허용/거부 여부를 최종 **판단**(신뢰 알고리즘 기반) |
| PA (Policy Administrator, 정책관리자) | PE의 판단에 따라 PEP에 접속 허용/차단 **지시** |
| PEP (Policy Enforcement Point, 정책시행지점) | 실제로 접근을 **집행**(허용/차단), 스스로 판단하지 않음 |

## 3. 동작 흐름

```
[사용자/기기] → 접근 요청 → [PEP]
                                │ 판단 요청
                                ▼
                            [PA] ←→ [PE] (신뢰 알고리즘으로 판단)
                                │
                          판단 결과 전달
                                ▼
                            [PEP] → 허용/차단 집행
```

## 4. NIST 7대 핵심 원칙 (요약)

1. 모든 데이터 소스와 컴퓨팅 서비스는 리소스로 간주
2. 네트워크 위치와 무관하게 모든 통신 보안
3. 리소스 접근은 세션 단위로 허가
4. 동적 정책(사용자/기기/행위 등 다중 요소)으로 접근 결정
5. 모든 자산의 무결성·보안상태 모니터링
6. 모든 리소스 인증/인가는 접근 전 **동적**으로 엄격히 시행
7. 자산 상태·네트워크 트래픽 정보를 수집해 보안태세 개선에 활용

## 암기 팁
- **"판-관-집"**: PE(**판**단)-PA(**관**리/지시)-PEP(**집**행) 순서로 역할 흐름 암기
- **"Zero Trust ≠ VPN 강화"** — 제로트러스트는 VPN을 대체/보완하는 아키텍처 개념이지 특정 제품이 아님
- **PEP는 판단하지 않는다** — 오직 PE/PA의 결정을 실행만 함(집행자일 뿐)

## 헷갈리는 포인트
- **"Zero Trust는 VPN을 더 강하게 만든 것"이라는 오해** — 제로트러스트는 경계 기반 사고 자체를 버리는 패러다임 전환, VPN 강화가 아님
- PEP가 스스로 접근 여부를 "판단"한다고 착각하기 쉬움 — 판단은 PE, PEP는 그저 **집행**만
- **마이크로세그멘테이션은 제로트러스트의 "정의"가 아니라 "구현 기법" 중 하나** — 개념과 구현수단을 혼동하지 않기

## 관련 기출/문제
- PE/PA/PEP 역할 구분
- "Never Trust, Always Verify"의 의미
- 전통적 경계보안과의 차이점
- 제로트러스트에 대한 흔한 오해(VPN강화 아님, 마이크로세그멘테이션=구현기법)
