# 방화벽 / IDS / IPS (침입차단시스템 4대 방식)

## 한줄 요약
> 방화벽은 동작 계층에 따라 패킷필터링(L3~4)-회선게이트웨이(L5)-응용게이트웨이(L7)-상태기반검사(L3~7 통합) 4가지로 나뉘며, 계층이 높을수록 정밀하지만 느려진다.

## 1. 방화벽 vs IDS vs IPS

| 구분 | 방화벽 (Firewall) | IDS (침입탐지시스템) | IPS (침입방지시스템) |
|---|---|---|---|
| 목적 | 접근 통제 (허용/차단) | 침입 탐지 (모니터링·경보) | 침입 탐지 + 실시간 차단 |
| 위치 | 네트워크 경계 (인라인) | 주로 미러링(passive) | 인라인(inline) |
| 대응 | 정책 기반 차단 | 사후 탐지·알림 | 실시간 자동 차단 |

## 2. 침입차단시스템(방화벽) 4대 구현 방식

### ① 패킷 필터링 (Packet Filtering)
- **동작 계층**: L3~L4
- **원리**: 패킷 헤더(출발지/목적지 IP, 포트, 프로토콜)만 검사해 ACL과 비교
- **대표 장비**: 스크리닝 라우터(Screening Router)
- **장점**: 빠름, 단순, 저렴, 서비스 독립적
- **단점**: 세션 상태 기억 못함, 페이로드 검사 불가, IP 스푸핑에 취약

### ② 회선 게이트웨이 (Circuit-Level Gateway)
- **동작 계층**: L5 부근
- **원리**: 클라이언트-서버 간 세션(회선) 연결 자체를 프록시가 중계, 세션 수립 후엔 내용 검사 없이 통과
- **대표 예시**: SOCKS
- **장점**: 응용게이트웨이보다 단순·빠름, 범용 프록시 하나로 여러 프로토콜 대응
- **단점**: 세션 수립 후 페이로드 미검사 → 응용계층 공격 취약

### ③ 응용 게이트웨이 (Application Gateway / Proxy)
- **동작 계층**: L7
- **원리**: 클라이언트-서버 직접연결 불허, 서비스별(HTTP/FTP 등) 프록시가 대리 수행
- **대표 구성**: 베스천 호스트(Bastion Host) 위에서 서비스별 프록시 데몬 운용
- **장점**: 페이로드까지 상세 검사, 정교한 접근제어, 로깅/감사 우수, 내부 구조 은닉
- **단점**: 서비스별 프록시 개별 구현 필요, 속도 저하, 낮은 투명성

### ④ 상태 기반 검사 (Stateful Inspection)
- **동작 계층**: L3~L7 통합 (현대 방화벽의 주류)
- **원리**: 헤더뿐 아니라 연결 상태(State)를 세션 테이블에 저장·추적, 이후 패킷이 기존 세션에 속하는지 판단
- **장점**: 패킷필터링보다 정교(세션하이재킹 탐지 가능), 응용게이트웨이보다 빠름 (커널 레벨), NGFW의 기본 방식
- **단점**: 세션 테이블 관리 부담, 응용게이트웨이만큼 세밀한 콘텐츠 검사는 제한적

## 3. 방식별 비교표

| 구분 | 패킷 필터링 | 회선 게이트웨이 | 응용 게이트웨이 | 상태 기반 검사 |
|---|---|---|---|---|
| 동작 계층 | L3~L4 | L5 | L7 | L3~L7 |
| 검사 대상 | 헤더 | 세션 정보 | 페이로드 전체 | 헤더+세션 상태 |
| 속도 | 빠름 | 빠름 | 느림 | 비교적 빠름 |
| 보안 수준 | 낮음 | 중간 | 높음 | 높음 |
| 서비스별 구현 | 불필요 | 불필요 | 필요 | 불필요 |
| 대표 예 | 스크리닝 라우터 | SOCKS | 베스천 호스트 프록시 | NGFW |

## 4. 관련 구성 개념

- **스크리닝 라우터**: 패킷 필터링 규칙을 적용하는 라우터
- **베스천 호스트(Bastion Host)**: 외부에 노출되는 유일한 접점 역할의 강화된 호스트
- **DMZ**: 외부 서비스(웹, 메일)를 내부망과 분리 배치하는 완충구역
- **Dual-Homed Gateway**: NIC 2개를 가진 베스천 호스트로 내부/외부망 물리적 분리, 라우팅 끄고 프록시로만 중계

## 5. IDS 탐지 방식

| 방식 | 원리 | 장점 | 단점 |
|---|---|---|---|
| 시그니처 기반(오용탐지) | 알려진 공격 패턴(DB)과 비교 | 오탐 적음, 빠름 | 신종 공격 탐지 못함 |
| 이상탐지(Anomaly) | 정상 기준선에서 벗어난 것 탐지 | 신종 공격도 탐지 가능 | 오탐(False Positive) 많음 |

- **NIDS**: 네트워크 트래픽 전체 감시 / **HIDS**: 개별 호스트 내부 감시

## 암기 팁
- **계층 순서**: "패킷필터(3~4)→회선게이트(5)→응용게이트(7)→상태기반(통합)" 계층 높을수록 정밀·느림
- **"패킷필터링=문패만 보고 통과, 응용게이트웨이=짐 속까지 검사, 상태기반검사=출입기록 대조"**
- IDS 탐지: **"시그니처=몽타주 대조, 이상탐지=평소와 다른 행동 감지"**

## 헷갈리는 포인트
- 회선 게이트웨이는 응용 게이트웨이보다 **검사 수준이 낮음** (세션만 관리, 내용 검사 안 함) — 이름이 비슷해서 헷갈리기 쉬움
- 상태 기반 검사는 패킷필터링의 "발전형"이지, 응용게이트웨이(프록시 방식)와는 원리가 다름 — 커널 레벨에서 세션 테이블로 처리
