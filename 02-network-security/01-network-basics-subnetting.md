# 네트워크 기초 / IPv4 서브네팅

## 한줄 요약
> 서브네팅은 호스트 비트 일부를 "빌려서" 네트워크를 여러 개로 쪼개는 것이다. 서브넷 개수 = 2ⁿ (n = 빌린 비트 수).

## 1. 핵심 공식

```
서브넷 개수 = 2ⁿ  (n = 호스트 부분에서 빌린 비트 수)
사용 가능한 호스트 수 = 2ʰ - 2  (h = 남은 호스트 비트 수, -2는 네트워크주소·브로드캐스트주소 제외)
새 prefix = 원래 prefix + n
```

**적용 순서**: ① 필요한 서브넷 개수 확인 → ② 2ⁿ=개수 되는 n 찾기 → ③ 원래 /prefix + n = 새 /prefix

## 2. /24 기준 자주 쓰는 표

| Prefix | 서브넷마스크 | 블록 크기 | 서브넷당 호스트 수(usable) |
|---|---|---|---|
| /24 | 255.255.255.0 | 256 | 254 |
| /25 | 255.255.255.128 | 128 | 126 |
| /26 | 255.255.255.192 | 64 | 62 |
| /27 | 255.255.255.224 | 32 | 30 |
| /28 | 255.255.255.240 | 16 | 14 |
| /29 | 255.255.255.248 | 8 | 6 |
| /30 | 255.255.255.252 | 4 | 2 |

## 3. 예제 1: 정방향 (192.168.16.0/20을 8개로 분할)

**1단계**: 8개 = 2³ → 비트 3개 빌림
**2단계**: 새 prefix = /20 + 3 = **/23**
**3단계**: 세 번째 옥텟에서 빌린 3비트가 000~111로 바뀌며 8개 서브넷 생성

```
192.168.16.0 이진수:
11000000 . 10101000 . 0001[0000] . 00000000
                          └┬┘└┬┘
                       고정  빌린3비트+남은1비트(호스트)
```

| # | 네트워크 주소 (/23) | 범위 |
|---|---|---|
| 1 | 192.168.16.0 | 16.0 ~ 17.255 |
| 2 | 192.168.18.0 | 18.0 ~ 19.255 |
| 3 | 192.168.20.0 | 20.0 ~ 21.255 |
| 4 | 192.168.22.0 | 22.0 ~ 23.255 |
| 5 | 192.168.24.0 | 24.0 ~ 25.255 |
| 6 | 192.168.26.0 | 26.0 ~ 27.255 |
| 7 | 192.168.28.0 | 28.0 ~ 29.255 |
| 8 | 192.168.30.0 | 30.0 ~ 31.255 |

**왜 2씩 증가?** → /23은 호스트 비트가 9개 남아서, 세 번째 옥텟에서는 1비트만 호스트로 남음 → 그 앞자리(서브넷 구분 비트)가 바뀔 때마다 세 번째 옥텟 값이 2씩 증가

## 4. 예제 2: 역방향 + 네트워크/브로드캐스트 주소 구하기 (200.107.26.17/18)

**서브넷마스크**: /18 → 255.255.192.0
**블록 크기**: 256 - 192 = **64**
**세 번째 옥텟(26)이 속한 블록 찾기**: 26 ÷ 64 = 몫 0 → 0~63 블록에 속함

→ **네트워크 주소**: 200.107.**0**.0
→ **브로드캐스트 주소**: 200.107.**63**.255

| 블록 범위 (세 번째 옥텟) | 네트워크 주소 |
|---|---|
| 0 ~ 63 | 200.107.0.0 |
| 64 ~ 127 | 200.107.64.0 |
| 128 ~ 191 | 200.107.128.0 |
| 192 ~ 255 | 200.107.192.0 |

## 암기 팁
- **정방향**: "필요한 개수 → 2의 몇 제곱인지 찾기 → prefix에 그 숫자 더하기"
- **역방향(네트워크주소 찾기)**: "256에서 서브넷마스크 빼서 블록크기 구하고, 몫으로 어느 블록인지 확인"
- "비트를 빌린 정확히 그 위치에서만 값이 증가한다" — 다른 비트는 이미 역할(네트워크 고정 / 순수 호스트)이 정해져 있어서 안 움직임

## 헷갈리는 포인트
- 서브넷마스크의 "256 - 마스크값" = 블록 크기 (예: 192 → 256-192=64)
- 몫(블록 번호)을 구할 때는 **정수 나눗셈의 몫**만 보면 됨, 나머지는 그 블록 안에서의 위치일 뿐

## 관련 기출/문제
- N개로 나눌 때 필요한 prefix 계산 (정방향)
- 주어진 IP가 속한 네트워크/브로드캐스트 주소 계산 (역방향)
- 특정 IP가 왜 특정 블록에서 벗어나는지 판단하는 경계값 문제
