# VPN / TLS / SSL - TLS 1.3

## 한줄 요약
> TLS 1.3은 핸드셰이크를 1-RTT(재접속시 0-RTT)로 줄이고, 취약한 옛날 알고리즘을 다 제거해서 더 빠르고 안전해졌다.

## 1. TLS 1.3 주요 개선점

**1) 핸드셰이크 속도 향상 (1-RTT)**
- TLS 1.2는 키 교환에 2-RTT(왕복) 필요 → TLS 1.3은 1-RTT로 단축
- 재접속 시에는 0-RTT(Zero Round Trip Time Resumption)도 지원

**2) 오래된 암호화 방식 제거**
- RSA 키 교환, RC4, DES, 3DES, MD5, SHA-1 등 취약한 알고리즘 삭제
- (Ephemeral) Diffie-Hellman 기반 키 교환만 지원 → **완전 순방향 비밀성(PFS)** 보장

**3) 핸드셰이크 암호화**
- TLS 1.2는 인증서 등 핸드셰이크 정보가 평문 노출
- TLS 1.3은 서버 인증서(Certificate) 부분부터 암호화

**4) 단순화된 암호 스위트**
- 5개의 강력한 암호 스위트로 정리 (예: TLS_AES_256_GCM_SHA384)
- AEAD(인증된 암호화) 방식만 사용

## 2. 핸드셰이크 흐름 (간략)

```
클라이언트                          서버
   |-- ClientHello + KeyShare ------>|
   |<-- ServerHello + KeyShare -------|
   |<-- {Certificate, Finished} ------|  (암호화됨)
   |-- {Finished} ------------------->|
   |<====== 암호화된 데이터 교환 ======>|
```

클라이언트가 처음부터 키 교환 정보(KeyShare)를 함께 보내기 때문에 왕복 횟수가 줄어듦.

## 3. 0-RTT 주의점

재접속 시 즉시 데이터를 보낼 수 있어 빠르지만, **재전송 공격(replay attack)**에 취약할 수 있음 → 멱등성이 보장되는 요청(GET 등)에만 사용 권장.

## 암기 팁
- **"1.3은 1-RTT, 재접속은 0-RTT"** — 숫자로 외우기
- **제거된 것들**: "RSA 키교환, RC4, DES/3DES, MD5, SHA-1" → 다 옛날 것들이라 버림
- **PFS 보장 이유**: Ephemeral(임시) DH만 쓰기 때문 — 매번 새 키 생성 → 과거 세션 키 유출돼도 안전

## 헷갈리는 포인트
- TLS 1.2에서는 **인증서가 평문**으로 노출됐지만, 1.3에서는 Certificate부터 암호화됨
- 0-RTT는 "빠르지만 재전송 공격에 취약" — 무조건 좋은 게 아님

## 관련 기출/문제
- TLS 1.2 vs 1.3 차이점 비교 문제
- TLS 1.3에서 제거된 알고리즘 목록
- 0-RTT의 보안 취약점
