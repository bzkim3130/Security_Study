# DNS 레코드 타입 정리

## 한줄 요약
> A/AAAA는 도메인→IP, PTR은 IP→도메인(역방향), MX는 메일서버, TXT는 SPF/DKIM/DMARC 같은 검증정보를 담는다.

## 1. 주요 레코드 타입

| 레코드 | 역할 |
|---|---|
| A | 도메인 → IPv4 주소 |
| AAAA | 도메인 → IPv6 주소 |
| CNAME | 별칭(도메인 → 다른 도메인) |
| MX | 메일 서버 지정 |
| NS | 해당 도메인의 네임서버 지정 |
| SOA | Zone의 관리정보(관리자, 시리얼 등) |
| PTR | IP → 도메인 (역방향 조회) |
| TXT | 임의 텍스트 정보 (SPF/DKIM/DMARC 등) |
| SRV | 특정 서비스의 위치(호스트+포트) 지정 |
| CAA | 이 도메인에 인증서 발급 가능한 CA 지정 |

## 2. DNS 조회 흐름 (정방향)

```
[Client] → "example.com의 IP는?" → [Local Resolver]
                                          │
                                    (캐시 없으면)
                                          ▼
                              [Root → TLD → Authoritative NS]
                                          │
                                    A 레코드 응답
                                          ▼
                                     [Client]
```

## 3. PTR (역방향 조회) — 포렌식 관점 중요

- IP 주소 → 도메인명을 알아내는 레코드 (정방향의 반대)
- 포렌식/침해사고 조사에서 **로그에 남은 IP가 실제 어떤 도메인이었는지 역추적**할 때 사용
- `in-addr.arpa` 특수 도메인을 이용해 조회

## 4. 이메일 인증 관련 TXT 레코드 (SPF/DKIM/DMARC)

| 레코드 | 역할 |
|---|---|
| SPF | 이 도메인이 허용한 메일 발신 서버 목록 |
| DKIM | 메일에 전자서명을 붙여 위변조 검증 |
| DMARC | SPF/DKIM 실패 시 처리 정책(격리/거부 등) 정의 |

→ 피싱 메일 판별, 이메일 포렌식 조사 시 자주 다뤄지는 개념

## 암기 팁
- **"A는 주소(Address), PTR은 거꾸로(Pointer, 역방향)"**
- **"MX는 메일(Mail eXchange)"**
- **SPF/DKIM/DMARC = "발신허용목록 - 서명검증 - 처리정책"** 3단 콤보로 암기

## 헷갈리는 포인트
- CNAME은 "별칭"이지 IP 자체를 담지 않음 — 최종적으로는 다시 A/AAAA 레코드를 조회해야 함
- PTR은 A레코드의 "역방향" 개념이지, A레코드를 자동으로 생성/연동해주는 게 아님 (별도로 설정해야 함)

## 관련 기출/문제
- 레코드 타입별 역할 매칭
- PTR 레코드의 포렌식 활용 (IP→도메인 역추적)
- SPF/DKIM/DMARC 역할 구분
