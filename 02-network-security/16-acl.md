# ACL (Access Control List) 적용 규칙

## 한줄 요약
> ACL은 위에서부터 순서대로 검사해 첫 번째로 일치하는 규칙(First Match)을 적용하고, 끝까지 안 걸리면 암묵적으로 차단(Implicit Deny)한다.

## 1. 기본 동작 원리

```
[패킷 도착]
     │
     ▼
[ACL 1번째 규칙 검사] ─ 일치? ─Yes→ 그 규칙 적용(허용/차단), 종료
     │ No
     ▼
[ACL 2번째 규칙 검사] ─ 일치? ─Yes→ 적용, 종료
     │ No
     ▼
    ...(계속 아래로)
     │
     ▼
[모든 규칙 불일치] → Implicit Deny (암묵적 차단, 마지막에 자동 존재)
```

- **First Match**: 위에서부터 순서대로 검사, **첫 번째로 일치하는 규칙**만 적용하고 이후 규칙은 검사 안 함
- **Implicit Deny**: 명시된 규칙에 하나도 안 걸리면 자동으로 차단 (마지막에 숨겨진 deny all 규칙이 있다고 생각)

## 2. Standard ACL vs Extended ACL 배치 전략

- **Standard ACL**: 출발지 주소만 검사 가능 → 목적지에 최대한 가깝게 배치 (너무 일찍 막으면 다른 트래픽까지 차단될 위험)
- **Extended ACL**: 출발지+목적지+포트+프로토콜까지 세밀하게 검사 가능 → 출발지에 최대한 가깝게 배치 (불필요한 트래픽을 초반에 차단해 효율적)

## 3. Wildcard Mask

서브넷마스크와 반대 개념 — **0은 정확히 일치해야 함, 1은 무시(아무값이나 허용)**

```
예: 192.168.1.0 0.0.0.255
→ 192.168.1.0~192.168.1.255 전체를 의미 (마지막 옥텟은 무시)
```

## 4. Numbered ACL vs Named ACL

| 구분 | Numbered ACL | Named ACL |
|---|---|---|
| 식별 방법 | 번호 | 이름 |
| 표준 ACL 번호 범위 | 1~99, 1300~1999 | - |
| 확장 ACL 번호 범위 | 100~199, 2000~2699 | - |
| 가독성 | 낮음 (숫자만) | 높음 (의미있는 이름) |
| 개별 규칙 수정 | 불가능 (전체 삭제 후 재작성 필요) | 가능 (sequence 번호로 특정 줄만 수정) |

**핵심 차이**: Named ACL은 시퀀스 번호를 이용해 **중간에 규칙 하나만 추가/삭제** 가능하지만, Numbered ACL은 전체를 지우고 다시 작성해야 함

## 암기 팁
- **"위에서부터 걸리는 첫 놈이 임자(First Match), 다 안 걸리면 자동으로 문 잠금(Implicit Deny)"**
- **배치 전략**: "Standard는 목적지 근처(정밀도 낮으니 조심), Extended는 출발지 근처(정밀하니 빨리 걸러도 안전)"
- **Named ACL = "이름표 붙여서 부분 수정 가능", Numbered = "번호만 있어서 통째로 다시 써야함"**

## 헷갈리는 포인트
- Wildcard mask의 0/1은 서브넷마스크와 **반대** — 서브넷마스크는 1이 네트워크부, 와일드카드는 0이 "정확히 일치해야 함"
- Standard/Extended ACL 배치 전략을 반대로 외우기 쉬움 — "정밀한 놈(Extended)을 먼저 걸러라"로 기억

## 관련 기출/문제
- First Match, Implicit Deny 개념 문제
- Standard/Extended ACL 배치 위치 이유
- Numbered vs Named ACL 수정 방식 차이
- Wildcard mask 계산 문제
