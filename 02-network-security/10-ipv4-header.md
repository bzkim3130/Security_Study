# IPv4 헤더 구조 및 필드 순서

## 한줄 요약
> IPv4 헤더의 첫 필드는 Version이며, "버·헤·서·총" 순서(Version-IHL-ToS-Total Length)로 앞 4개 필드를 암기한다.

## 1. IPv4 헤더 구조 (도식)

```
 0               8               16                          31
┌───────┬───────┬───────────────┬───────────────────────────┐
│Version│  IHL  │      ToS       │       Total Length          │
├───────┴───────┴───────────────┼───────────┬─────────────────┤
│         Identification         │  Flags    │  Fragment Offset │
├───────────────┬────────────────┼───────────┴─────────────────┤
│      TTL       │   Protocol     │        Header Checksum       │
├───────────────┴────────────────┴───────────────────────────┤
│                    Source Address                             │
├───────────────────────────────────────────────────────────┤
│                    Destination Address                        │
├───────────────────────────────────────────────────────────┤
│                    Options (있을 경우) + Padding                │
└───────────────────────────────────────────────────────────┘
```

## 2. 앞 4개 필드 순서/의미

| 순서 | 필드 | 크기 | 의미 |
|---|---|---|---|
| 1 | Version | 4비트 | IP 버전 (IPv4=4) |
| 2 | IHL (Header Length) | 4비트 | 헤더 길이(4바이트 단위) |
| 3 | ToS (Type of Service) | 8비트 | 서비스 우선순위/QoS |
| 4 | Total Length | 16비트 | 전체 패킷(헤더+데이터) 길이 |

**시험 함정**: "IPv4 데이터그램의 첫 필드는 헤더 길이(IHL)다" → **틀림**, 첫 필드는 **Version**

## 3. IPv6 헤더와의 차이

- IPv6은 헤더가 **고정 40바이트** (IPv4는 가변, Options 필드로 늘어날 수 있음)
- IPv6은 **Checksum 필드 제거** (상위/하위 계층에서 이미 오류검출 하므로 중복 제거, 처리속도 향상)
- IPv6은 확장 헤더(Extension Header) 방식으로 옵션 기능 처리 (IPv4의 Options 필드보다 유연)

## 암기 팁
- **"버·헤·서·총"**: Version → Header Length(IHL) → 서비스타입(ToS) → 총길이(Total Length)
- **"첫 글자는 항상 버전(Version)"** — IPv4/IPv6 둘 다 맨 앞 4비트는 버전 필드

## 헷갈리는 포인트
- IHL이 "헤더 길이 필드"이자 동시에 "맨 처음 필드"라고 착각하기 쉬움 — 순서상 **Version이 먼저**, IHL은 두 번째
- IPv6이 체크섬을 없앤 건 "보안을 포기해서"가 아니라, 상위 계층(TCP/UDP)에서 이미 오류검출을 하기 때문에 중복 제거한 것 (효율성 목적)

## 관련 기출/문제
- IPv4 헤더 첫 필드가 무엇인지 (Version, IHL 아님)
- IPv4 vs IPv6 헤더 구조 차이 (고정/가변, 체크섬 유무)
- 앞 4개 필드 순서 나열 문제
