# TCP/IP 계층별 공격

## 한줄 요약
> 공격은 계층마다 노리는 지점이 다르다 — 물리/링크는 스니핑·스푸핑, 네트워크는 경로 조작, 전송은 세션/자원 고갈, 응용은 서비스 자체를 노린다.

## 1. 계층별 공격 정리

```
응용 계층    : DNS 스푸핑, 피싱, 웹 취약점 공격(SQLi, XSS)
전송 계층    : SYN Flood, 세션 하이재킹
네트워크 계층 : IP 스푸핑, ICMP Flood, Smurf 공격
데이터링크 계층: ARP 스푸핑, MAC 플러딩
물리 계층     : 도청, 케이블 탈취/훼손
```

| 계층 | 대표 공격 | 핵심 원리 |
|---|---|---|
| 응용 | DNS 스푸핑 | 가짜 DNS 응답으로 사용자를 악성 사이트로 유도 |
| 전송 | SYN Flood | 3-way handshake의 SYN만 대량 전송, ACK 없이 방치 → 서버 자원 고갈 |
| 전송 | 세션 하이재킹 | 정상 세션의 시퀀스 번호를 탈취해 세션 가로채기 |
| 네트워크 | IP 스푸핑 | 출발지 IP주소를 위조해 신뢰관계 악용 |
| 네트워크 | Smurf 공격 | 위조된 출발지 IP로 ICMP 브로드캐스트 → 다수 응답이 피해자에게 집중 |
| 데이터링크 | ARP 스푸핑 | 가짜 ARP 응답으로 MAC-IP 매핑 조작 → 중간자 공격(MITM) |
| 데이터링크 | MAC 플러딩 | 위조 MAC 대량 전송으로 스위치 MAC테이블 오버플로우 → 허브처럼 브로드캐스트 유도 |

## 2. SYN Flood 상세

```
공격자                        서버
  │── SYN (위조 출발지 다수) ──▶│
  │                            │ SYN-ACK 응답 준비, 대기큐에 쌓임
  │  (ACK 응답 안 옴) ✗        │
  │                            │ 대기큐 가득 참 → 정상 연결 처리 불가
```

**대응**: SYN 쿠키(SYN Cookie), 방화벽에서 연결 속도 제한

## 3. ARP 스푸핑 상세

```
정상: PC-A ─ARP Request(누가 IP-B?)→ 네트워크
      PC-B ─ARP Reply(나야, MAC-B)→ PC-A

공격: 공격자 ─위조 ARP Reply(나야, 사실은 내 MAC)→ PC-A
      → PC-A는 공격자를 PC-B로 오인, 트래픽이 공격자 경유
```

**대응**: 정적 ARP 테이블 설정, ARP 스푸핑 탐지 툴

## 4. DoS/DDoS 공격 확장 정리

### 4-1. 자원 고갈형 (Flooding)

| 공격 | 원리 |
|---|---|
| SYN Flood | SYN만 대량 전송, ACK 없이 방치 → 서버 연결 큐 고갈 |
| UDP Flood | 대량 UDP 패킷 전송 → 대역폭/처리자원 고갈 |
| ICMP Flood | 대량 ICMP Echo Request 전송 → 응답 처리 부하 |

### 4-2. 비정상 패킷(프로토콜 조작)형

| 공격 | 원리 |
|---|---|
| Teardrop | 조각화(Fragmentation)된 IP 패킷의 오프셋 값을 조작해 재조립 시 시스템 오류 유발 |
| Bonk | Teardrop의 변형, UDP 패킷 조각의 순서/오프셋을 조작해 재조립 실패 유발 (주로 포트 53 등 대상) |
| Boink | Bonk의 확장판, 여러 포트에 대해 유사한 방식으로 공격 |
| Land | 출발지 IP·포트와 목적지 IP·포트를 동일하게 위조 → 시스템이 자기 자신에게 응답을 반복하며 자원 고갈 |
| Ping of Death | 규격보다 큰(65,535바이트 초과) ICMP 패킷을 조각내어 전송 → 재조립 시 버퍼 오버플로우 유발 |

```
[Teardrop 계열 원리]
정상 조각화: [조각1: 0~999] [조각2: 1000~1999] [조각3: 2000~2999]  → 순서대로 재조립 OK

Teardrop/Bonk/Boink: [조각1: 0~999] [조각2: 500~1499(겹침/역전)]  → 재조립 로직 오류 → 시스템 다운/행
```

### 4-3. 반사/증폭형 (Reflection/Amplification)

| 공격 | 원리 |
|---|---|
| Smurf | 출발지 IP를 피해자로 위조한 ICMP Echo Request를 브로드캐스트 주소로 전송 → 다수 호스트의 응답이 피해자에게 집중 |
| Fraggle | Smurf와 원리 동일하지만 ICMP 대신 UDP(주로 echo/chargen 포트) 사용 |

```
공격자 → (출발지 IP 위조: 피해자IP) → 브로드캐스트 주소로 ICMP/UDP 전송
           │
           ▼
   네트워크 내 모든 호스트가 "피해자"에게 일제히 응답 전송
           │
           ▼
      피해자 = 트래픽 폭주로 마비
```

## 암기 팁
- **계층 낮을수록 물리적/네트워크 조작, 계층 높을수록 서비스/콘텐츠 조작**
- **"SYN은 반쯤 열린 문 쌓아서 막기"**, **"ARP는 주소록 조작해서 도청"**, **"Smurf는 대신 때려달라고 부탁(브로드캐스트 악용)"**
- **"본크·보인크는 형제, 티어드롭 사촌"** — 셋 다 조각화 재조립 오류 계열
- **"Land = 부메랑 공격"** (자기 자신에게 던진 걸 자기가 계속 맞음, 출발지=목적지)
- **Smurf vs Fraggle**: "스머프는 아이씨엠피(ICMP), 프래글은 유디피(UDP)" — 원리는 같고 프로토콜만 다름

## 헷갈리는 포인트
- IP 스푸핑과 ARP 스푸핑은 다른 계층 공격 — IP스푸핑은 네트워크 계층(3계층) 주소 위조, ARP스푸핑은 데이터링크 계층(2계층) 주소 위조
- SYN Flood는 "대역폭"이 아니라 "서버의 연결 대기 자원(큐)"을 고갈시키는 공격
