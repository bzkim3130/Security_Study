# 공개키 암호의 두 가지 활용 방식 (전자서명 vs 전자봉투)

## 한줄 요약
> "내 개인키로 암호화하면 인증/부인방지(전자서명)", "상대방 공개키로 암호화하면 기밀성(전자봉투)" — 누구 키를 쓰느냐에 따라 목적이 완전히 달라진다.

## 1. 핵심 한 문장

```
자신의 개인키로 암호화     →  인증 + 부인방지  (전자서명)
상대방의 공개키로 암호화   →  기밀성           (전자봉투)
```

## 2. 방식 ① 송신자가 자신의 개인키로 암호화 (전자서명)

```
[송신자] --메시지 해시를 자신의 개인키로 암호화(서명)--> [수신자]
                                                            │
                                              송신자의 공개키로 복호화(검증)
```

| 제공 서비스 | 이유 |
|---|---|
| 인증 (Authentication) | 그 개인키를 가진 사람만 이 서명을 만들 수 있음 |
| 부인방지 (Non-repudiation) | 개인키는 본인만 소유 → "안 보냈다" 발뺌 불가 |
| 무결성 (Integrity) | 보통 메시지 전체가 아닌 해시값을 서명 → 변조 여부도 확인됨 |

**주의**: 이 방식은 **기밀성은 제공 안 함** — 송신자의 공개키는 누구나 가질 수 있어서 원문을 누구나 확인 가능

## 3. 방식 ② 송신자가 수신자의 공개키로 암호화 (전자봉투)

```
[송신자] --메시지를 수신자의 공개키로 암호화--> [수신자]
                                                    │
                                        수신자 자신의 개인키로 복호화
```

| 제공 서비스 | 이유 |
|---|---|
| 기밀성 (Confidentiality) | 수신자의 개인키를 가진 사람(수신자 본인)만 복호화 가능 |

**주의**: 이 방식은 **인증/부인방지는 제공 안 함** — 수신자의 공개키는 공개정보라 누구든 암호화해서 보낼 수 있음 (송신자가 누군지 보장 안 됨)

## 4. 비교표

| 구분 | 개인키로 암호화 | 수신자 공개키로 암호화 |
|---|---|---|
| 암호화 키 | 송신자의 개인키 | 수신자의 공개키 |
| 복호화 키 | 송신자의 공개키 | 수신자의 개인키 |
| 목적 | 인증, 부인방지 (전자서명) | 기밀성 |
| 열람 가능자 | 누구나 (공개키만 있으면) | 수신자 본인만 |
| 제공 못하는 것 | 기밀성 | 인증, 부인방지 |

## 5. 실무에서는 둘 다 함께 씀 (하이브리드)

```
1. 송신자: 메시지 해시를 자신의 개인키로 서명 (인증+부인방지)
2. 송신자: (메시지+서명)을 수신자의 공개키로 암호화 (기밀성)
3. 수신자: 자신의 개인키로 복호화
4. 수신자: 송신자의 공개키로 서명 검증
```
→ PGP, S/MIME 등이 이 방식 사용

## 암기 팁
- **"내 열쇠로 잠그면 내가 보냈다는 증명(서명), 니 자물쇠로 잠그면 너만 열 수 있다(봉투)"**
- 개인키(Private) = "나만 가진 것" → 서명/부인방지 담당
- 공개키(Public) = "다들 가진 것" → 암호화해서 보내면 그 짝 개인키 가진 사람만 열람(기밀성) 담당

## 헷갈리는 포인트
- "공개키 암호화 = 무조건 기밀성"이 아님 — **누구의 키로 암호화했는지**가 핵심
- 전자서명은 메시지 원문이 아니라 **해시값**을 서명하는 것이 일반적 (연산량 때문)

## 관련 기출/문제
- "송신자가 개인키로 암호화했다"는 지문 → 인증/부인방지 (기밀성 아님, 함정주의)
- "수신자의 공개키로 암호화했다"는 지문 → 기밀성 (인증 아님, 함정주의)

## 💬 내 코멘트
- PGP ( OpenPGP 고유 형식 / 개인이 직접 키 생성 )
- S/MIME ( X.509 인증서 / CA가 인증서 발급(신원확인절차 포함) )
