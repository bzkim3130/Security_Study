# HSM (Hardware Security Module)

## 한줄 요약
> HSM은 암호키를 물리적으로 격리된 전용 하드웨어 안에서만 생성·저장·연산하게 만든 장비로, PKI Root키·금융결제 시스템 등 "절대 유출되면 안 되는 키" 보관에 쓰인다.

## 1. 핵심 기능

- 암호키 생성/저장/파기를 전용 하드웨어 내부에서만 수행 (키가 하드웨어 밖으로 평문으로 나가지 않음)
- 암복호화/서명 연산도 HSM 내부에서 처리 → 메인 서버는 결과값만 받음

## 2. 물리적 보안 메커니즘

| 메커니즘 | 내용 |
|---|---|
| Tamper-evident | 물리적 개봉 시도 흔적이 남음 |
| Tamper-resistant | 물리적 공격에 저항하도록 설계(에폭시 봉인 등) |
| Tamper-response / Zeroization | 침입 감지 시 내부 키를 즉시 자동 삭제 |

## 3. HSM vs TPM

| 구분 | HSM | TPM |
|---|---|---|
| 형태 | 별도 전용 하드웨어(서버/카드) | 메인보드에 내장된 칩 |
| 용도 | 서버급 대량 키 관리, PKI Root, 금융 | 개별 PC/기기의 부팅 무결성, 디스크 암호화 키 |
| 처리 성능 | 높음(다수 트랜잭션 처리) | 낮음(개별 기기용) |
| 대표 사례 | CA Root키 보관, 결제 시스템 | BitLocker, Secure Boot |

## 4. 관련 인증/표준

- **FIPS 140-2/3**: 미국 정부 암호모듈 검증 표준, 레벨 1~4
- **Common Criteria (CC)**: 국제 공통평가기준
- **KCMVP**: 한국 암호모듈 검증제도 (국내 표준)

## 5. 구조 (개념도)

```
[메인 서버/애플리케이션]
        │  (암호화 요청만 전달, 키 자체는 안 보임)
        ▼
   ┌─────────────┐
   │     HSM      │  ← 물리적으로 격리된 전용 장비
   │  (키 생성/저장/연산 전부 내부에서)  │
   └─────────────┘
```

## 암기 팁
- **"HSM = 은행 금고, TPM = 개인 지갑 속 작은 자물쇠"** — 규모와 용도가 다름
- **탬퍼 3단계**: "흔적(evident) → 저항(resistant) → 자폭(zeroization)" 순서로 강도가 세짐

## 헷갈리는 포인트
- HSM은 "암호화를 빠르게 해주는 가속기"가 아니라 **"키를 안전하게 격리 보관하는 것"**이 본질 목적
- TPM이 있다고 HSM이 필요없는 게 아님 — 개별 기기용(TPM)과 서버/기관용(HSM)은 목적 자체가 다름

- Tamper-evident/resistant/response 구분
