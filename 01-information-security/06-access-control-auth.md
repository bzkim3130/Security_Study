# 접근통제 / 인증 - S/Key OTP 방식

## 한줄 요약
> S/Key는 해시를 여러 번 연쇄로 적용한 값을 미리 준비해두고, 매 로그인마다 한 단계씩 거꾸로 꺼내 쓰는 일회용 비밀번호(OTP) 방식이다.

## 1. S/Key 개요

| 항목 | 내용 |
|---|---|
| 개발 | 1980년대 후반, Bell Communications Research |
| 목적 | 일회용 비밀번호(OTP)로 재전송(replay) 공격 방지 |
| 표준 | RFC 1760, RFC 2289 |
| 핵심 원리 | 연쇄 해시(chained hash) 함수 기반 |

## 2. 동작 원리

1. 사용자가 초기 시드(seed/passphrase)를 정함
2. 해시 함수(MD4/MD5 등)를 시드에 **N번 반복 적용**해서 최종값을 만듦
3. 서버는 이 N번째 해시값(또는 그 다음 값)을 저장
4. 로그인할 때마다 사용자는 **한 단계 적은 횟수로 해시한 값**을 제출
5. 서버는 받은 값을 한 번 더 해시해서 저장된 값과 일치하는지 비교
6. 일치하면 인증 성공, 저장값을 방금 받은 값으로 갱신 (다음 로그인 대비)

```
초기 시드 → Hash → Hash → ... → Hash (N번)
                                    │
                              서버에 저장 (N번째 값)

로그인 1회차: 사용자가 (N-1)번째 해시값 제출
             → 서버가 한 번 더 해시 → N번째 값과 비교 → 일치하면 통과
             → 서버는 저장값을 (N-1)번째 값으로 갱신

로그인 2회차: 사용자가 (N-2)번째 해시값 제출
             → 위와 동일하게 검증 후 갱신
             ...
```

**핵심**: 매번 다른 값(한 단계씩 거꾸로)을 쓰기 때문에, 도청당해도 **재사용이 불가능** (재전송 공격 방지)

## 3. 한계점

- 시퀀스가 소진되면(N번 다 쓰면) 재초기화 필요
- 실시간 중간자 공격(MITM)에는 여전히 취약할 수 있음
- 서버에 저장된 값 자체가 유출되면 위험

## 암기 팁
- **"한 번 쓰고 버리는 계단 내려가기"**: N번째부터 시작해서 로그인할 때마다 한 칸씩 아래(N-1, N-2...)로 내려가는 값을 제출
- 해시를 여러 번 감아놓고(chained hash) 매번 한 겹씩 벗겨서 인증 → 도청해도 다음 겹은 미리 못 만듦 (해시의 역방향 계산 불가능 특성 이용)

## 헷갈리는 포인트
- S/Key는 "매번 새 비밀번호를 서버가 발급"하는 게 아니라, **이미 정해진 해시 체인에서 순서대로 꺼내 쓰는** 방식
- 해시 함수의 일방향성(역산 불가) 덕분에, 공격자가 (N-1)번째 값을 가로채도 (N-2)번째 값을 계산할 수 없음

## 관련 기출/문제
- S/Key가 재전송 공격에 강한 이유 (매번 다른 값 사용 + 해시 역산 불가)
- S/Key의 한계 (시퀀스 소진, MITM 취약 가능성)
