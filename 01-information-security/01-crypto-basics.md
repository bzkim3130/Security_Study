# 암호학 기초 (대칭키 vs 비대칭키) + ITU-T X.800

## 한줄 요약
> 암호 알고리즘은 크게 대칭키(블록/스트림)와 공개키(비대칭키)로 나뉘고, X.800은 이를 지키기 위한 "공격-서비스-메커니즘" 표준 프레임워크다.

## 1. 암호 알고리즘 분류

```
암호 알고리즘 (Cryptography)
│
├── 대칭키 암호 (Symmetric-key)  ─ 암호화/복호화에 같은 키 사용
│    │
│    ├── 블록암호 (Block Cipher)
│    │     예: AES, DES, 3DES, SEED, ARIA
│    │     → 데이터를 고정 크기 블록 단위로 암호화
│    │
│    └── 스트림암호 (Stream Cipher)
│          예: RC4, ChaCha20, Salsa20
│          → 데이터를 비트/바이트 단위로 순차 암호화
│
└── 공개키(비대칭키) 암호 (Asymmetric-key / Public-key)
     예: RSA, ECC, ElGamal, Diffie-Hellman
     → 암호화/복호화에 서로 다른 키(공개키/개인키) 사용
     → 블록암호와 무관한 별도 구조 (수학적 난제 기반)
```

**핵심 포인트**
- 블록암호 ⊂ 대칭키 암호 (하위 분류일 뿐)
- 공개키 암호는 대칭키와 완전히 다른 범주 → 블록암호 아님

## 2. ITU-T X.800 보안 아키텍처

OSI 7계층 기반의 보안 표준 프레임워크. **"공격 - 서비스 - 메커니즘"** 3박자가 핵심.

```
X.800 보안 아키텍처
├── ① 보안 공격 (Security Attack)   → "위협이 뭐냐"
├── ② 보안 서비스 (Security Service) → "뭘 지킬거냐"
└── ③ 보안 메커니즘 (Security Mechanism) → "어떻게 지킬거냐"
```

### ① 보안 공격 (2가지)

| 구분 | 특징 | 종류 | 대응 전략 |
|---|---|---|---|
| 소극적 공격 (Passive) | 도청형, 탐지 어려움 | 도청(내용유출), 트래픽 분석 | 예방 중심 |
| 적극적 공격 (Active) | 변조/조작형, 탐지는 쉬움 | 위장, 재전송, 메시지 변조, 서비스거부(DoS) | 탐지·복구 중심 |

### ② 보안 서비스 (6가지)

```
인증(Authentication) — 너 누구냐
접근통제(Access Control) — 들어와도 되냐
기밀성(Confidentiality) — 못 보게
무결성(Integrity) — 못 바꾸게
부인방지(Non-repudiation) — 발뺌 못하게
가용성(Availability) — 언제든 쓸 수 있게
```

### ③ 보안 메커니즘 (2 유형)

| 유형 | 의미 | 예시 |
|---|---|---|
| 특정 보안 메커니즘 | 특정 서비스에 맞춤 적용 | 암호화, 전자서명, 접근통제, 데이터무결성, 인증교환, 트래픽패딩, 라우팅통제, 공증 |
| 포괄적 보안 메커니즘 | 특정 서비스 국한 안됨, 전반적 | 신뢰기능성, 보안레이블, 이벤트탐지, 보안감사추적, 보안복구 |

## 암기 팁
- **암호 분류**: "블록암호는 대칭키의 자식, 공개키는 완전히 남남"
- **X.800 순서**: "공-서-메" → 공격을 알아야 → 서비스(목표)를 정하고 → 메커니즘(수단)으로 막는다
- **공격 2종**: "소극적 = 몰래 듣기만(막기 어려움→예방!), 적극적 = 직접 건드림(흔적 남음→탐지!)"
- **보안 서비스 6개 두문자**: "인접기무부가" (인증-접근통제-기밀성-무결성-부인방지-가용성)

## 헷갈리는 포인트
- 공개키 암호는 "비대칭키 블록암호"가 아니다 — 아예 다른 범주
- 소극적 공격은 예방(암호화)으로 막고, 적극적 공격은 탐지·복구(인증, 무결성 검증)로 대응

## 관련 기출/문제
- "공개키 대칭키 둘 다 블록암호냐?" → 아니오. 공개키는 블록암호가 아니다.
- 시험에서는 "이 공격은 소극적/적극적?", "이 서비스명은 뭐?" 매칭 문제로 자주 출제됨
