# 블록암호 / 스트림암호 (DES, AES, RC4, 운영모드)

## 한줄 요약
> 블록암호는 고정 크기 블록 단위로, 스트림암호는 비트/바이트 단위로 순차 암호화한다. 블록암호는 "운영모드"에 따라 스트림처럼 동작할 수도 있다.

## 1. 기본 구조: Feistel vs SPN

| 구분 | Feistel | SPN (Substitution-Permutation Network) |
|---|---|---|
| 대표 알고리즘 | DES, HIGHT, RC5, LOKI | AES, SEED, ARIA, LEA |
| 암/복호화 구조 | 동일 구조 (라운드키 순서만 역순) | 별도의 역연산 필요 |
| 처리 방식 | 블록을 좌우 절반으로 나눠 순차 처리 | 블록 전체를 한번에 병렬 처리 |
| 하드웨어 구현 | 상대적으로 단순 (암복호화 회로 공유 가능) | 별도 역연산 회로 필요, 구현 복잡 |

```
[Feistel 구조]                    [SPN 구조]
입력 → 좌/우 분할                  입력 (전체 블록)
  좌 ─┐                                │
      XOR ← F(우, 키)              치환(S-box)
  우 ─┘                                │
   (좌우 교체, 반복)                환치(P-box)
                                        │
                                    (라운드 반복)
```

**시험 함정**: HIGHT는 한국 표준(경량암호)이지만 **Feistel 구조**, AES는 **SPN 구조가 확정적** — "국산 알고리즘이니까 SPN일 것"이라 착각하기 쉬움

## 2. 블록암호 알고리즘 스펙 비교

| 알고리즘 | 블록 크기 | 키 길이 | 라운드 수 | 구조 |
|---|---|---|---|---|
| DES | 64비트 | 56비트 | 16 | Feistel |
| 3DES | 64비트 | 112/168비트 | 48(16×3) | Feistel |
| AES | 128비트 | 128/192/256비트 | 10/12/14 | SPN |
| IDEA | 64비트 | 128비트 | 8 | (독자 구조) |
| Blowfish | 64비트 | 32~448비트(가변) | 16 | Feistel |
| SEED | 128비트 | 128비트 | 16 | Feistel |
| ARIA | 128비트 | 128/192/256비트 | 12/14/16 | SPN |
| LEA | 128비트 | 128/192/256비트 | 24/28/32 | SPN (경량) |
| HIGHT | 64비트 | 128비트 | 32 | Feistel (경량) |

```
블록 크기로 분류
├── 64비트: DES, 3DES, IDEA, Blowfish, HIGHT
└── 128비트: AES, SEED, ARIA, LEA
```

## 3. 블록암호 운영 모드 (Mode of Operation)

| 모드 | 암호화 병렬처리 | 복호화 병렬처리 | 오류 전이(전파) | IV 필요 |
|---|---|---|---|---|
| ECB | 가능 | 가능 | 해당 블록만 영향 | 불필요 |
| CBC | 불가능 | 가능 | 해당 블록 + 다음 블록 영향 | 필요 |
| CFB | 불가능 | 가능 | 해당 블록 + 다음 블록 영향 | 필요 |
| OFB | 불가능 | 불가능 | 전이 없음 (해당 비트만) | 필요 |
| CTR | 가능 | 가능 | 전이 없음 (해당 비트만) | 필요(nonce) |

### 모드별 핵심 특징
- **ECB**: 평문 패턴이 암호문에 그대로 드러남 (가장 취약), 가장 단순
- **CBC**: 가장 널리 쓰임, 평문 블록을 이전 암호문과 XOR
- **CFB / OFB**: 스트림 암호처럼 동작, 블록 단위 패딩 불필요
- **CTR**: 카운터 값 사용, 병렬처리 최고 효율, 랜덤 접근 가능

**중요 포인트**: CFB, OFB, CTR은 복호화할 때도 **암호화 함수(Enc)**를 사용한다 (Dec 함수 아님) → 이 때문에 스트림 암호처럼 동작 가능.

## 4. 스트림암호

| 항목 | 내용 |
|---|---|
| 대표 알고리즘 | RC4(사용 중단), ChaCha20, Salsa20 |
| 처리 단위 | 비트/바이트 단위 순차 처리 |
| 현재 상태 | RC4는 취약점으로 인해 TLS 등 최신 프로토콜에서 제거됨. AES를 CTR/GCM 모드로 쓰면 스트림 암호처럼 동작 |

## 5. 기타 자주 나오는 개념
- 눈사태 효과 (Avalanche Effect): 입력 1비트가 바뀌면 출력이 대폭 바뀌는 성질
- 키 스케줄 (Key Schedule): 라운드마다 사용할 서브키를 생성하는 과정
- 패딩 방식: PKCS#5 / PKCS#7

## 암기 팁
- **오류 전이**: "CBC/CFB는 2블록(옆집까지 영향), ECB는 1블록(자기만), OFB/CTR은 영향 없음(독립적)"
- **복호화에 Enc 쓰는 모드**: "C-O-C-T (CFB, OFB, CTR)는 복호화도 암호화 함수로!"
- **Feistel vs SPN**: "Fe(DES)는 대칭이라 편함, SPN(AES)은 치환+환치 반복"
- **"HIGHT는 이름은 첨단인데 구조는 옛날식 Feistel"** — 함정 대비
- **블록크기 128비트 그룹**: "AES, SEED, ARIA, LEA (최신/국산 계열은 다 128비트)"

## 헷갈리는 포인트
- ECB가 "가장 안전해 보이지만" 사실 패턴 노출로 실무에서 거의 안 씀
- OFB와 CTR 둘 다 "전이 없음"이지만, OFB는 복호화 병렬처리 **불가능**, CTR은 **가능** (카운터 기반이라 순서 상관없이 계산 가능)

## 관련 기출/문제
- "전송 중 1비트 오류 발생 시 복호화에 몇 블록 영향?" → CBC/CFB는 2블록, ECB는 1블록만, OFB/CTR은 영향 없음
- RC4가 TLS 1.3에서 제거된 이유 (보안 취약점)
- Feistel vs SPN 구조 대표 알고리즘 매칭 (HIGHT=Feistel 함정주의)
- 알고리즘별 블록크기/키길이/라운드수 암기
