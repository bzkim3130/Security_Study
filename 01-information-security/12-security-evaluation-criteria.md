# 정보보호 시스템 평가 표준 (TCSEC → ITSEC → CC)

## 한줄 요약
> 미국의 TCSEC(오렌지북)과 유럽의 ITSEC이 각자 따로 발전하다가, 국제 표준 CC(Common Criteria, ISO/IEC 15408)로 통합됐다.

## 1. 발전 흐름

```
TCSEC (오렌지북, 1985, 미국)
   │  기능성+보증성을 등급 하나로 묶어 평가(D~A1)
   ▼
ITSEC (1991, 유럽)
   │  기능성과 보증성을 분리 평가 시작
   ▼
CC / Common Criteria (ISO/IEC 15408, 현재 국제표준)
   │  TOE, PP, ST, EAL 체계로 통합
```

## 2. TCSEC (오렌지북)

| 등급 | 의미 |
|---|---|
| D | 최소 보호 (평가 안 됨) |
| C1, C2 | 임의적 접근통제(DAC) |
| B1, B2, B3 | 강제적 접근통제(MAC) |
| A1 | 검증된 설계 (최고 등급) |

## 3. CC (Common Criteria) 핵심 용어

| 용어 | 의미 |
|---|---|
| TOE (Target of Evaluation) | 평가 대상 제품/시스템 |
| PP (Protection Profile) | 소비자가 요구하는 보안 요구사항 명세 |
| ST (Security Target) | 개발자가 작성하는 실제 구현 명세 (PP를 만족해야 함) |
| EAL (Evaluation Assurance Level) | 평가 보증 등급, 1~7단계 |

**PP와 ST의 관계**: PP(소비자 요구) → ST(개발자가 이를 만족시키도록 작성) — **방향성이 중요** (PP가 먼저, ST가 이를 따름)

## 4. EAL 등급표

| 등급 | 의미 |
|---|---|
| EAL1 | 기능시험 |
| EAL2 | 구조시험 |
| EAL3 | 체계적 테스트 |
| EAL4 | 체계적 설계·시험·검토 |
| EAL5 | 준정형화 설계 |
| EAL6 | 준정형화 검증된 설계 |
| EAL7 | 정형화 검증된 설계 (최고 등급) |

**핵심 함정**: EAL 등급이 높다고 "보안 기능이 더 많다"는 뜻이 아님 — **"검증(평가)의 엄격함/깊이"**를 나타내는 것

## 5. 국내 인증 기관

- **ITSCC (IT Security Certification Center)**: 국가정보원 산하, 국내 CC 인증 담당 기관

## 암기 팁
- **발전 순서**: "TCSEC(미국,오렌지북) → ITSEC(유럽) → CC(국제통합)"
- **EAL = 등급 높다고 기능 많은 게 아니라 검증이 빡세다는 뜻**
- **"PP는 손님 주문서, ST는 셰프의 레시피"** — 손님 주문(PP)을 셰프가 레시피(ST)로 구현

## 헷갈리는 포인트
- EAL 등급 ≠ 보안 기능의 강력함, **평가(검증)의 엄격도**를 의미
- PP와 ST를 헷갈리기 쉬움 — PP는 "요구", ST는 "구현/응답"

## 관련 기출/문제
- TCSEC/ITSEC/CC 발전 순서 및 국가 매칭
- EAL 등급의 의미(기능성 아닌 검증 엄격도)
- PP vs ST 방향성 문제
