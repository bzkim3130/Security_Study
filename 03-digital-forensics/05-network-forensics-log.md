# 네트워크 포렌식 / 로그 분석

## 한줄 요약
> 네트워크 포렌식은 "패킷 자체(pcap)"와 "장비/서버가 남긴 로그" 두 축으로 이루어지며, 시간 동기화(NTP)가 안 맞으면 로그 상관분석 자체가 무너진다.

## 1. 네트워크 포렌식 데이터 소스

| 소스 | 담긴 정보 |
|---|---|
| 패킷 캡처 (pcap) | 실제 오간 트래픽 원본, Wireshark 등으로 분석 |
| 방화벽 로그 | 허용/차단된 연결 기록 (출발지·목적지 IP, 포트) |
| IDS/IPS 로그 | 탐지된 공격 시그니처, 이상행위 기록 |
| 웹서버 로그 (Access Log) | 요청 IP, URL, User-Agent, 응답코드, 시각 |
| 프록시 서버 로그 | 내부 사용자의 외부 접속 기록 |
| DNS 로그 | 도메인 조회 기록 (악성 도메인 접속 여부 확인) |
| DHCP 로그 | IP-MAC 할당 이력 (특정 시점에 어느 PC가 어느 IP였는지) |

## 2. 분석 흐름

```
[사건 인지] → [관련 로그 소스 식별]
                     │
       ┌─────────────┼─────────────┐
       ▼             ▼             ▼
   방화벽 로그    웹서버 로그      pcap 캡처
       │             │             │
       └─────────────┼─────────────┘
                      ▼
            [시간 동기화 후 상관분석 (Correlation)]
                      │
                      ▼
            [공격 흐름 재구성 / 타임라인 작성]
```

## 3. 핵심 개념

- **NTP (시간 동기화)**: 여러 장비의 로그를 대조하려면 시각이 정확히 맞아야 함 — 안 맞으면 사건 순서 자체가 왜곡됨
- **로그 상관분석 (Log Correlation)**: 서로 다른 소스의 로그를 시간·IP 등 공통 키로 엮어서 하나의 사건 흐름으로 재구성
- **NetFlow / sFlow**: 패킷 전체가 아닌 "트래픽 요약 정보"(누가 누구와 언제 얼마나 통신했는지)를 기록 — 용량 부담 적어 장기 보관에 유리

## 4. 웹서버 로그(Access Log) 필드 예시

```
192.168.1.10 - - [03/Aug/2026:10:15:32 +0900] "GET /login.php HTTP/1.1" 200 512
     │                    │                        │           │    │
  클라이언트IP          접속시각                  요청내용   상태코드 응답크기
```

## 암기 팁
- **"pcap = 원본 그대로, 로그 = 요약된 기록"**
- **시간 동기화(NTP) 안 맞으면 모든 분석이 무너진다** — 네트워크 포렌식의 첫 단추
- 로그 소스 암기: **"방화벽(허용/차단) - IDS(탐지) - 웹서버(요청기록) - DNS(도메인조회) - DHCP(IP할당)"**

## 헷갈리는 포인트
- NetFlow는 패킷 전체를 저장하는 게 아니라 **통신 메타데이터(요약)**만 저장 — pcap과 저장 목적이 다름
- 방화벽 로그는 "차단된 것"만이 아니라 **허용된 연결도 기록**될 수 있음 (설정에 따라 다름)

## 관련 기출/문제
- 로그 소스별로 어떤 정보가 담기는지 매칭
- NTP 동기화가 중요한 이유
- pcap vs NetFlow 차이
