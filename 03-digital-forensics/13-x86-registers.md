# 80386(x86) 레지스터 구조

## 한줄 요약
> 범용레지스터(EAX~EDI), 포인터레지스터(ESP/EBP), 세그먼트레지스터(CS/DS/SS/ES/FS/GS), 제어/상태레지스터(EIP/EFLAGS/CR0~4)로 구성되며, 리버싱/포렌식에서는 EBP(스택프레임 기준점)와 ESP(스택 최상단)의 구분이 핵심이다.

## 1. 레지스터 분류

| 분류 | 레지스터 | 역할 |
|---|---|---|
| 범용 레지스터 | EAX, EBX, ECX, EDX, ESI, EDI | 연산, 데이터 저장 |
| 포인터 레지스터 | ESP(스택포인터), EBP(베이스포인터) | 스택 관리 |
| 세그먼트 레지스터 | CS, DS, SS, ES, FS, GS | 메모리 세그먼트 지정 |
| 제어/상태 레지스터 | EIP(명령어포인터), EFLAGS(플래그), CR0~CR4(제어) | 실행 흐름/상태 제어 |

## 2. EAX 서브레지스터 계층

```
        EAX (32비트 전체)
         │
        AX (하위 16비트)
       ┌─┴─┐
      AH   AL   (각 8비트: 상위/하위)
```
- 같은 원리로 EBX→BX→BH/BL, ECX→CX→CH/CL, EDX→DX→DH/DL

## 3. ESP vs EBP

| 구분 | ESP (Stack Pointer) | EBP (Base Pointer) |
|---|---|---|
| 역할 | 스택의 **최상단(top)** 을 가리킴 | 현재 함수의 **스택 프레임 기준점**을 가리킴 |
| 변화 | PUSH/POP마다 계속 이동 | 함수 진입 시 고정, 함수 종료까지 안 변함 |
| 용도 | 실제 스택 연산 | 지역변수/매개변수에 **상대주소**로 접근하는 기준 |

**함수 진입 시 전형적 프롤로그**
```
PUSH EBP          ; 이전 함수의 EBP 저장
MOV EBP, ESP       ; 현재 ESP를 새 기준점(EBP)으로
SUB ESP, N         ; 지역변수 공간 확보
```

## 4. 주요 레지스터 상세

- **EIP (Instruction Pointer)**: 다음에 실행할 명령어 주소 — 리버싱에서 실행 흐름 추적의 핵심, 버퍼오버플로우 공격의 최종 목표(EIP 덮어쓰기)
- **EFLAGS**: 연산 결과 상태 플래그(Zero Flag, Carry Flag, Sign Flag 등) — 조건분기(JZ, JNZ 등) 판단 기준
- **CR0~CR4**: 프로세서 동작 모드 제어(보호모드 전환, 페이징 활성화 등)

## 암기 팁
- **EAX 계열 계층**: "EAX(32) → AX(16) → AH/AL(8+8)" — 상위/하위로 계속 반씩 쪼개짐
- **"ESP는 계속 움직이는 꼭대기, EBP는 함수 안에서 안 움직이는 기준점"**
- **함수 프롤로그 3줄 세트**: "PUSH EBP → MOV EBP,ESP → SUB ESP,N" 통째로 암기

## 헷갈리는 포인트
- ESP와 EBP를 혼동하기 쉬움 — ESP는 계속 변하는 "지금 스택 꼭대기", EBP는 함수 진입 시 고정되는 "이 함수만의 기준점"
- EIP는 레지스터지만 직접 MOV로 값을 바꿀 수 없음 — JMP, CALL, RET 등 제어흐름 명령을 통해서만 간접적으로 변경됨(버퍼오버플로우가 이 원리를 악용)

## 관련 기출/문제
- ESP/EBP 역할 구분
- EAX 서브레지스터 계층 구조
- 함수 프롤로그의 스택프레임 설정 순서
- EIP가 리버싱/공격에서 갖는 의미
