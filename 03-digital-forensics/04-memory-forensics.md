# 메모리 포렌식

## 한줄 요약
> 메모리(RAM)에는 실행 중인 프로세스, 네트워크 연결, 암호화 키, 악성코드 흔적 등 디스크에는 없는 "휘발성 증거"가 남아있어 반드시 전원 끄기 전에 수집해야 한다.

## 1. 메모리 포렌식이 중요한 이유

| 디스크에 없고 메모리에만 있는 정보 |
|---|
| 실행 중인 프로세스/스레드 목록 |
| 열려 있는 네트워크 연결(소켓) 정보 |
| 복호화된 암호/키 (디스크엔 암호화된 채로만 존재) |
| 인메모리(파일리스) 악성코드 흔적 |
| 클립보드 내용, 최근 명령어 히스토리 |

## 2. 메모리 수집 방법

- **하드웨어 기반**: 별도 장비로 물리 메모리 직접 덤프
- **소프트웨어 기반**: 툴(예: FTK Imager, DumpIt, WinPmem 등)로 실행 중인 시스템에서 메모리 이미지(.mem/.raw) 생성
- **수집 원칙**: 시스템을 종료하지 않은 상태에서, 최대한 적은 메모리 변경으로 수집 (수집 행위 자체도 메모리를 일부 건드리므로 최소 침습 원칙)

## 3. 메모리 분석으로 알아낼 수 있는 것

```
메모리 이미지 분석
├── 프로세스 목록/트리 구조 (부모-자식 관계)
├── 로드된 DLL/모듈 목록
├── 네트워크 연결 상태 (열린 포트, 접속 IP)
├── 레지스트리 하이브 일부
├── 커맨드 히스토리 / 클립보드
└── 은닉 프로세스(Rootkit) 탐지 (프로세스 목록 API 결과와 실제 메모리 구조 비교)
```

## 4. 대표 분석 도구

- **Volatility**: 대표적인 오픈소스 메모리 포렌식 프레임워크 (플러그인 기반, pslist/netscan 등)
- **Rekall**: Volatility와 유사한 메모리 분석 프레임워크

## 암기 팁
- **"디스크는 정적 증거, 메모리는 동적 증거"** — 메모리에만 있는 게 뭔지가 핵심 포인트
- **수집 순서 원칙**: "휘발성 높은 것부터" → 메모리가 디스크보다 항상 먼저
- Volatility의 **pslist**(프로세스 목록), **netscan**(네트워크 연결) 정도는 이름 기억해두기

## 헷갈리는 포인트
- 메모리 수집 행위 자체도 메모리 상태를 일부 변경시킴 → "완벽하게 원본 그대로"는 불가능, 최소 침습으로 접근하는 게 원칙
- 파일리스(Fileless) 악성코드는 디스크에 흔적이 없어 메모리 분석 없이는 탐지 자체가 불가능한 경우가 많음

## 관련 기출/문제
- 메모리에만 남는 정보 vs 디스크에 남는 정보 구분
- 휘발성 순서에서 메모리의 위치
- Volatility 같은 분석 도구의 역할
