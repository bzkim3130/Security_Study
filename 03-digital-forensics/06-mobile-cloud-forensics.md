# 모바일 / 클라우드 포렌식

## 1. 모바일 포렌식

## 한줄 요약
> 모바일 포렌식은 비행기 모드 전환 후 페러데이 백에 격리해 원격 삭제·통신을 차단하는 것이 첫 단계다.

### 초동 조치
```
[기기 확보] → [비행기 모드 전환 (가능하면)]
                       │
                       ▼
          [페러데이 백(전자파 차단 파우치)에 격리]
                       │
                       ▼
        (원격 초기화·삭제 명령 수신 차단, 배터리 방전 방지 위해 충전기 연결)
```
- **페러데이 백(Faraday Bag)**: 전자파를 차단해 기기가 네트워크에 연결되지 못하게 하는 장비 → 원격 삭제(리모트 와이프) 공격 방지

### 데이터 추출 방식

| 방식 | 접근 수준 | 특징 |
|---|---|---|
| Physical (물리) | 가장 낮은 수준(비트단위) | 저장소 전체 이미징, 삭제된 데이터도 복구 가능성 있음 |
| File System (파일시스템) | 파일시스템 구조 접근 | 파일/폴더 단위로 접근, 물리보다 제한적 |
| Logical (논리) | 앱/OS API 통해 접근 | 백업 데이터 수준, 가장 제한적이지만 가장 안전(기기 손상 위험 적음) |

### 주요 아티팩트
- 통화기록, 문자메시지(SMS), 메신저 앱 DB (SQLite 파일)
- 위치정보 (GPS 로그, Wi-Fi 접속 이력)
- 앱 사용 기록, 설치 목록

## 2. 클라우드 포렌식

## 한줄 요약
> 클라우드는 물리적으로 서버를 압수할 수 없는 경우가 많아, 서비스 제공자(CSP) 협조나 API를 통한 원격 수집이 핵심이다.

### 클라우드 포렌식의 특수성

| 구분 | 전통적 포렌식 | 클라우드 포렌식 |
|---|---|---|
| 데이터 위치 | 물리적으로 특정 가능 | 여러 지역/서버에 분산 저장 가능 |
| 접근 방법 | 기기 직접 압수 | CSP(서비스 제공자) 협조 또는 API 접근 |
| 관할권 | 국내 단일 | 데이터센터 위치에 따라 국제 관할권 문제 발생 가능 |
| 로그 확보 | 로컬 로그 직접 확보 | CSP가 제공하는 접속/API 로그에 의존 |

### 데이터 수집 방법
- **CSP 협조 요청**: 법적 절차(영장 등)로 서비스 제공자에게 데이터 제공 요청
- **API 기반 수집**: 계정 접근 권한이 있는 경우, 클라우드 제공 API로 직접 수집(예: 구글 Takeout류)
- **동기화된 로컬 기기 활용**: 클라우드와 동기화된 PC/모바일에서 캐시된 데이터 확보

## 암기 팁
- **모바일**: "비행기모드 → 페러데이백" 세트로 암기 (원격삭제 차단이 핵심)
- **추출 방식 3단계**: "Physical(다 봄) > FileSystem(구조만) > Logical(앱이 주는 것만)" — 왼쪽일수록 깊고 위험 부담도 큼
- **클라우드**: "데이터가 어디 있는지도 모른다 → 그래서 CSP 협조가 핵심"

## 헷갈리는 포인트
- Physical 추출이 가장 많은 정보(삭제 데이터 포함)를 주지만, 최신 스마트폰은 암호화 때문에 Physical 추출 자체가 매우 어려운 경우가 많음
- 클라우드 데이터는 관할권 문제로 국내 영장만으로 해외 서버 데이터를 바로 못 가져오는 경우가 있음 (국제공조 필요)

## 관련 기출/문제
- 페러데이백의 목적
- 모바일 데이터 추출 3방식 비교
- 클라우드 포렌식에서 관할권 문제가 생기는 이유
