# 리버스 엔지니어링 / 안티 리버싱 / 안티 디버깅 관계

## 한줄 요약
> 리버스엔지니어링(RE) ⊃ 안티 리버싱 ⊃ 안티 디버깅 — 포함관계이며, 안티디버깅은 안티리버싱의 여러 기법 중 하나일 뿐이다.

## 1. 핵심 관계

| 개념 | 정의 | 관계 |
|---|---|---|
| 리버스 엔지니어링 | 바이너리/프로그램을 분석해 원리·구조·로직을 역으로 파악하는 행위 | 최상위 개념 |
| 안티 리버싱 | RE를 "어렵게" 만들려는 방어 기법들의 총칭 | 안티디버깅을 포함하는 상위 카테고리 |
| 안티 디버깅 | 안티 리버싱 기법 중 "디버거 탐지/차단"에 특화된 하위 기법 | 안티리버싱의 한 종류 |

## 2. 도식화

```
리버스 엔지니어링(RE)
├── 정적 분석 (디스어셈블러: IDA)
└── 동적 분석 (디버거: OllyDbg, x64dbg)

안티 리버싱 (Anti-Reversing) — RE를 방해하는 모든 기법
├── 안티 디버깅 — 디버거(동적분석) 탐지/방해
├── 안티 디스어셈블리 — 디스어셈블러(정적분석) 방해
├── 코드 난독화 (Obfuscation)
├── 패킹/암호화 (Packing)
└── 안티 VM — 가상환경 탐지
```

## 3. 정적분석 vs 동적분석 방해 매칭

| 분석 방식 | 도구 | 방해 기법 |
|---|---|---|
| 정적분석(디스어셈블) | IDA 등 | 안티 디스어셈블리, 패킹 |
| 동적분석(디버거로 실행 추적) | OllyDbg, x64dbg 등 | 안티 디버깅 |

## 4. 대표 안티 디버깅 기법

- `IsDebuggerPresent()`, `CheckRemoteDebuggerPresent()` — API 기반 탐지
- 타이밍 체크(RDTSC) — 디버깅 시 실행 지연을 이용한 탐지
- SEH(구조적 예외처리) 이용
- INT 3(브레이크포인트) 탐지

## 암기 팁
- **"RE는 목적, 안티리버싱은 방패, 안티디버깅은 그 방패 중 하나"**
- **우산 비유**: 안티리버싱(우산) 밑에 여러 우산살(안티디버깅, 안티디스어셈블리, 난독화, 패킹, 안티VM)이 있다고 기억

## 헷갈리는 포인트
- **"안티 디버깅 = 안티 리버싱"으로 오해하기 쉬움** — 안티디버깅은 안티리버싱의 **일부**일 뿐, 패킹·난독화·안티VM도 안티리버싱에 포함됨
- 정적분석 방해와 동적분석 방해를 헷갈리기 쉬움 — 안티디버깅은 **동적분석(디버거)** 전용 방해기법

## 관련 기출/문제

- 대표 안티디버깅 API/기법 (IsDebuggerPresent 등)
